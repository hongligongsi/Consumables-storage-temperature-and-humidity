# 温控与功率安全

控制器由主循环每 50 ms 调用一次。仓温 PID 与发热板 PID 在同一周期、使用同一个
采样时间 `dt` 计算；`dt` 被限制在 10–250 ms，避免偶发调度抖动放大积分或微分项。

## 双 PID 协同

- 仓温 PID：设定值为当前耗材的最低仓温，输出代表加热需求。
- 发热板 PID：设定值为“发热板温度保护”，输出代表当前允许的安全功率。
- 合成输出：`min(仓温 PID, 发热板 PID, 用户功率上限)`。

因此，即使仓温仍然较低，只要发热板接近保护温度，最终功率也会受发热板 PID
限制。发热板达到保护阈值或仓温达到耗材最高温度时，状态机进入安全排气并立即
停止加热；PID 只是渐进控制，不能替代硬保护。

## 过流软降

INA226 电流读取使用绝对值，兼容采样方向相反的接线。当电流超过设置上限时：

```text
限流后功率 = PID 合成功率 × 设定电流 / 实测电流
```

该比例在阈值处连续，不会像硬切断一样造成输出反复跳变。限流后的目标还会经过
每 50 ms 最大 3% 的 PWM 斜率限制，逐步降低功率。INA226、NTC 或 AHT20 任一安全
输入无效时不使用软降，而是当周期立即输出 0；传感器恢复后从 0% 重新爬升。

## 硬保护与故障码

软保护（安全排气、过流软降）负责把工况拉回可控范围；当它压不住时，控制器在
`HARD_TRIP_MS`（0.5 s）后锁定 `Fault` 并停止加热。硬保护判据相对软限值留有余量，
这样正常工况下软保护先动作、两者不会抢动作，单次采样尖峰也不会误报：

| 判据              | 阈值                  | 故障码                     |
| --------------- | ------------------- | ----------------------- |
| 热板温度            | 保护温度 + 15 ℃         | F-03 `BoardOverTemp`    |
| 仓温              | 耗材仓温上限 + 15 ℃       | F-04 `ChamberOverTemp`  |
| 加热电流            | 上限 × 1.5            | F-05 `OverCurrent`      |
| AHT20 / NTC / INA226 读数无效 | 预热或打印中连续 3 s | F-01 / F-02 / F-06      |

进入 `Fault` 时判定一次故障码并保持到复位；判定优先级是「硬过温 > 硬过流 >
传感器掉线」，越危险的越先报，掉线判据自带 valid 前置所以不会掩盖真实超温。
故障码在屏上故障页、REST `/api/state` 的 `fault` 字段与 MQTT `event` 主题三处
对外可见，排查时不必连串口。编号**就是枚举值本身**（`AhtLost`=1 → `F-01`，
`None`=0 只是哨兵），故新增码只能追加在 `FaultCode::Count` 之前。

复位有两条路径，效果并不相同：

- **故障页长按编码器键** → 调用 `clearFault()`。热类故障（F-03/F-04/F-05）复位
  后先进 `Cooling` 安全姿态，保持 100 % 排气与热板风扇，直到温度回落到软限
  以下 —— 故障态本来就全速排风，若直接回 `Idle`，排风与热板风扇会立刻停，
  等于把设备置于比故障态更热的姿态。热类分支**故意保留硬保护计时**，条件仍在
  时下一控制周期（50 ms）立即复锁，所以不会出现“复位后一段无排风”的空窗；
  传感器/采样掉线类（F-01/F-02/F-06）没有余热要排，直接回 `Idle`。
- **关闭系统总使能** → 走 `update()` 里的 `!systemEnabled_` 分支，直接回 `Idle`
  并清空全部计时与故障码（人工断电，温控不再参与）。

两条路径都会清除故障码、故障计时与 PID 历史。锁定期间故障页只放行长按复位与
系统总开关（后者是人工断电入口，若一并拦掉就再也够不着“关闭系统”），其余
输入一律忽略。

## NVS 故障记忆（断电保持锁定）

每次锁定故障都会写入 NVS（`FaultRecord`：故障码、是否仍锁定、累计锁定次数、
发生时刻）。两个用途：

- **防止拔电绕过保护**：热类故障（F-03/F-04/F-05）若在锁定状态下断电重启，
  `setup()` 读取记录后调用 `restoreFault()` 直接回到 `Fault` 态并显示原故障码，
  输出层自动进入全速排风的安全姿态，仍须长按复位或关系统才能解锁。传感器
  掉线类（F-01/F-02/F-06）**不恢复锁定** —— 开机本来就会重新检测传感器，
  恢复了也只会被新判定立即覆盖，开机时顺手清掉 latch 标志、保留历史记录。
- **排障历史**：复位只清 latch 标志，故障码 / 累计次数 / 最近一次发生时刻都
  保留在 NVS，通过 `/api/state` 的 `lastFault` / `faultCount` /
  `lastFaultEpoch` 字段（或串口 `[FAULT]` 日志）可查；恢复出厂设置时清除。

判据与边界：`ChamberController::persistsAcrossReboot()` 决定哪些码跨重启恢复
（与 `clearFault()` 的热类判定同一批）；`lastFaultEpoch` 在时钟不可用（NTP 未
同步且从未手动校时）时为 0；NVS 写失败只打串口日志不重试 —— 记忆是安全增强
而非前提，不能拖住 50 ms 热控节拍。

## PID 状态清理

待机、检测、冷却、故障、关闭自动温控或传感器无效时，两个 PID 的积分、微分历史
与 PWM 历史都会清零，避免长时间停机被错误计入下一次温控。
