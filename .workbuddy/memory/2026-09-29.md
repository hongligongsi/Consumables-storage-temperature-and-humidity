## 排查烧录中断：pySerial PermissionError(13, '拒绝访问')

现象：esptool 写到 `0x0013354a`（93%）时中断，报 `Cannot configure port` /
`PermissionError(13, '拒绝访问')`。

定位过程与结论：

- 对照 `.pio/build/esp32-s3-n16r8/firmware.bin` = 1,271,408 字节（本日 15:18 编译）。
  报错偏移 `0x13354a - 0x10000 = 1,193,290` = 镜像的 93.9%，确认是写 `app0` 途中断线，
  最后约 78 KB 未写入。→ **app0 处于半截损坏状态**，上电校验不过会回滚 app1，
  app1 为空则反复重启，必须重烧。
- 分区表用的是 PlatformIO 版 `default_16MB.csv`（`~/.platformio/packages/framework-arduinoespressif32/tools/partitions/`）：
  `app0/app1 = 0x640000`（6.25 MB），固件仅占 19%，**无空间压力**。
  （区别于 Arduino 官方同名文件里的 0x140000，判断占用率时别搞混。）
- 根因方向：Windows 串口句柄中途失效（被其他进程占用，或 USB 掉线/重枚举、USB 节能挂起），
  非 esptool / 固件问题。

已做的修改：

1. `platformio.ini`：新增 `upload_speed = 460800`（原为默认 921600），并加了说明注释。
   最稳的复测值是 115200。
2. `docs/build-and-flash.md`：新增「串口写入中断（PermissionError 13）」排查章节，
   含 7 条排查顺序 + 「掉线 vs 被占用」判据（COM 号是否跳变）。
3. `README.md` 常见问题：新增同主题问答，指向上面文档的锚点。

## 排查「连上 ESP32 却看不到 WiFi」：PSRAM 大块分配挂死

现象：烧录成功后设备每 2~3 秒重启一次（`rst:0x8 TG1WDT_SYS_RST`），
`network.begin()` 卡在 `WiFi.mode(WIFI_STA)` 之前，WiFi 热点始终不出现。

三层根因，逐层剥开：

1. **TFT_eSPI 在 S3 上 SPI 端口选错 → StoreProhibited 崩溃**
   `CONFIG_IDF_TARGET_ESP32S3` 只存在于 sdkconfig.h、不会传给编译器，TFT 退回通用
   `TFT_eSPI_ESP32.h`；`SPI_PORT=FSPI(=1)`，而 IDF `soc.h` 的 `REG_SPI_BASE(i)` 只对
   `i>=2` 映射（i=1 得 0），TFT 自带的 `#ifndef REG_SPI_BASE` 补丁因 soc.h 已定义而失效
   → `SPI_USER_REG = 0x10`，`init()` 里 `SET_BUS_WRITE_MODE` 往地址 16 写寄存器 → 崩溃。
   修：`-DCONFIG_IDF_TARGET_ESP32S3=1 -DUSE_FSPI_PORT`。反汇编验证寄存器地址
   从 `0x10` 变成 `0x60024010`。

2. **看不到应用日志**：`-DARDUINO_USB_CDC_ON_BOOT=1` 让 `Serial` 走 S3 原生 USB-CDC，
   不在 FTDI 的 COM4 上。临时注释该宏即可用 UART0 抓日志（已恢复，注释里写明切换方法）。
   注意：ESP-IDF 的 `log_e`（如 ADC 报错）走 console UART0，与 Arduino `Serial` 无关，
   所以 CDC 打开时 COM4 仍会吐 IDF 日志。

3. **本板 8MB OPI PSRAM 硬件不可用（真正的 WiFi 卡死根因）**
   `heap_caps` 上报 PSRAM free=8386035、200B 分配正常，但 **64KB 起的大块分配直接把
   总线挂死**并触发任务看门狗。内部 RAM 完全正常（free=313908、largest=286708，64KB OK）。
   而 `qio_opi` 变体的 sdkconfig 有 `CONFIG_SPIRAM_TRY_ALLOCATE_WIFI_LWIP=1`，
   WiFi/LWIP 缓冲区正是往 PSRAM 分配 → `WiFi.mode(WIFI_STA)` 必死。
   修：SDK 换 `qio_qspi` 变体（PSRAM 走 QSPI 时序初始化，本板物理 OPI 必失败 →
   `psramFound()=0`、不并入堆），并去掉 `-DBOARD_HAS_PSRAM` / `-DCONFIG_SPIRAM_SUPPORT=1`。
   验证：`memB malloc 64K SPIRAM` 从「卡死」变成 `ptr=0x0`，随后
   `net2 wifi.mode done` → `[NET] WiFiManager started, AP fallback SSID=FilamentChamber-Setup`。

修改落地：

- `platformio.ini`：`memory_type=qio_qspi`、`psram_type=qspi`、去掉两个 PSRAM 宏、
  恢复 `ARDUINO_USB_CDC_ON_BOOT`，并写了完整的根因注释（含换板后如何改回）。
- `src/tft_ui.cpp`：全屏 sprite 用 `#if defined(TFT_SPRITE_IN_PSRAM)` 门控跳过，
  落到直绘降级分支（PSRAM 修好后加该宏即可恢复双缓冲）。
- `src/network.cpp` / `src/main.cpp`：临时 MARK 打印已清理，逻辑零改动。

坑：**platformio.ini 里 `build_flags =` 的第一个续行不能以 `;` 开头**，
否则该 option 收不到值，后续 `-D` 行会被挂到上一个 option（表现为
`partitions.bin Source 'default_16MB.csv\n-DXXX...' not found`）。

（上面 9-22 记的「遗留 ADC_NTC=39」已于当日下午解决，见下节；
以下遗留项仍然有效：AHT20 / INA226 未检测到。）
